# BMSPORT YVN Diagnostic Reports

В репозитории две версии: нативное приложение iOS и отдельная веб-версия. Запуск веб-версии и её возможности описаны в [docs/WEB.md](docs/WEB.md).

**Windows:** готовая локальная сборка доступна в [Releases](https://github.com/KarenMkrtchyan666/bmsport-yvn/releases). Распакуйте ZIP и запустите `START-WINDOWS.cmd`: Node.js, OCR и модели перевода включены, внешний сервер не нужен. Для исходников используйте `SETUP-WINDOWS.cmd`, затем `START-WINDOWS.cmd`.

**iOS:** [перенесённые функции и ограничения](docs/IOS-UPDATE.md). Нужны Mac/Xcode для сборки и подписи. Новые поля совместимы со старыми отчётами; автоперевод использует iOS 18+, базовое приложение поддерживает iOS 17. Проверку сборки смотрите во вкладке Actions.

Нативное приложение для iPhone и iPad: Swift, SwiftUI, SwiftData, UIKit/Core Text. Минимальная версия iOS 17. У нативного приложения нет сервера, WebView, HTML, PWA, внешних библиотек и сетевой передачи данных. Функциональность реализована по требованиям пользователя и сверена с доступными в workspace `public/app.js`, `server/pdf.js`, `config/service.json`, `docs/CONTEXT.md`. Имеющийся веб-проект остаётся отдельным: Xcode не использует его файлы или Node.js. Автоматического переноса его SQLite-истории на iPhone пока нет.

## Запуск и установка на реальный iPhone без App Store

1. Перенесите **всю папку проекта** на Mac с Xcode 16+ и установленным iOS SDK, совместимым с вашим iPhone. На Windows собрать и подписать iOS-приложение этим проектом нельзя.
2. Откройте `BMSport.xcodeproj`. Готовый проект и общая схема уже включены; генераторы и пакеты устанавливать не нужно.
3. В Xcode → Settings → Accounts добавьте Apple Account. В target **BMSport** → Signing & Capabilities включите Automatically manage signing, выберите свою Team и замените Bundle Identifier на уникальный (например `am.yourname.bmsport`). Для тестов на устройстве выберите ту же Team у тестовых targets.
4. Подключите iPhone к Mac, подтвердите доверие. Включите на телефоне Settings → Privacy & Security → Developer Mode, если Xcode попросит, и перезагрузите телефон. При необходимости подтвердите разработчика в Settings → General → VPN & Device Management.
5. В Xcode выберите схему **BMSport**, свой iPhone в качестве устройства и нажмите **Run (⌘R)**. После успешной сборки приложение устанавливается на iPhone и запускается своей иконкой. После установки Mac не нужен для обычной работы, но подпись должна оставаться действующей.
6. Personal Team подходит для личной установки, но подпись ограничена по сроку и требует повторного запуска через Xcode после истечения. Для распространения на зарегистрированные устройства используйте Apple Developer Program и Ad Hoc: зарегистрировать UDID → Archive → Distribute App → зарегистрированные устройства. Это отдельный процесс подписи; готовый подписанный IPA в репозиторий не включён.

Официальные инструкции Apple: [запуск на устройстве](https://developer.apple.com/documentation/xcode/running-your-app-on-simulated-or-physical-devices), [учётная запись](https://developer.apple.com/help/account/basics/about-your-developer-account), [распространение на зарегистрированные устройства](https://developer.apple.com/documentation/xcode/distributing-your-app-to-registered-devices).

**Текущее состояние:** исходный проект создан на Windows. Сборка, подпись и установка на iPhone ещё не выполнены. Для реальной установки нужен Mac, iPhone и Apple Account; утверждения о готовой установленной сборке нет.

## Работа

- `+` открывает новый отчёт. Имя, телефон, марка/модель, год и пробег обязательны для завершения и PDF. VIN и госномер необязательны; введённый VIN проверяется по длине и допустимым символам.
- Черновик допускает незаполненные поля. Автосохранение происходит через 650 мс после изменения, при уходе в фон и закрытии. Редактирование завершённого отчёта переводит его в черновик при следующем сохранении. Кнопка «Завершить отчёт» снова проверяет поля.
- Добавляйте ошибки до работ, описание и переключатель «Устранена / Осталась». Коды намеренно не ограничены OBD-II: допустимы заводские BMW-коды.
- История сортируется по времени изменения. Поиск: имя, телефон, модель, VIN, госномер. Откройте строку для редактирования.
- «PDF / Поделиться» сохраняет завершённый отчёт, создаёт отдельный файл A4 и открывает UIActivityViewController. Выберите AirDrop, «Сохранить в Файлы», WhatsApp или Telegram, если они установлены и поддерживают передачу PDF. Набор действий определяет iOS.

## Хранение и восстановление

SwiftData хранит отчёты в sandbox приложения. Явные сохранения показывают ошибки, без `try!`, `fatalError` и сброса базы. Повреждённый payload отображается в истории как повреждённый и не заменяется пустым отчётом. Ошибка открытия базы показывает экран восстановления; рабочая база не удаляется. CloudKit выключен.

Перед сохранением SwiftData записывается независимый JSON-журнал `Library/Application Support/Recovery/<UUID>.json` с полным содержимым, версией схемы и статусом. Предыдущая версия сохраняется рядом как `.previous.json`. Файлы записываются атомарно с iOS Complete File Protection. Если запись журнала не удалась, сохранение останавливается и редактор показывает ошибку. При ошибке SwiftData журнал может содержать более новую версию, чем история: это намеренно, чтобы сохранить возможность восстановления.

Для восстановления разработчик может получить контейнер приложения через Xcode → Devices and Simulators → Installed Apps → Download Container и прочитать JSON-журнал. Автоматического импорта повреждённой базы или журнала пока нет. Не удаляйте приложение при ошибке: удаление удаляет локальный контейнер. Локальный журнал не заменяет внешнюю резервную копию; сохраняйте важные PDF в Files/AirDrop и резервируйте iPhone. Клиентские данные не логируются. Отправляемый PDF содержит персональные данные выбранного отчёта.

## PDF и шрифты

UIGraphicsPDFRenderer создаёт A4 595.276 × 841.89 pt. Core Text разбивает поток на страницы по фактически вместившимся символам, включая очень длинные абзацы. На каждой странице есть бренд, город, Instagram, номер отчёта и страницы. Заголовки русские/армянские, пользовательские поля поддерживают Unicode. Системный шрифт iOS и каскад Core Text подбирают армянские глифы без загрузок. Внешние шрифты не нужны. Итоговый вид армянских глифов нужно визуально проверить на целевой версии iOS: текстовое извлечение PDF не заменяет визуальный контроль.

## Проверки

На Windows выполнены: генерация `.pbxproj` и shared scheme, проверка ссылок и файлов проекта, XML схемы, статический просмотр исходников. **Swift-компиляция, unit/UI-тесты и визуальная проверка PDF на iOS здесь не запускались**, поскольку Xcode и iOS Simulator отсутствуют.

Подготовлены unit-тесты: валидация, JSON round trip черновика, создание/редактирование/чтение SwiftData после повторного открытия контейнера, обработка повреждённого payload, экспорт файла, многостраничный A4 и извлечение русского/армянского текста из PDF. UI-тесты: создание, поиск, открытие, вызов Share Sheet, ошибка валидации. UI-тесты используют отдельное in-memory хранилище и не трогают рабочую базу. Это означает, что сохранение между запусками проверяет unit-тест с дисковым контейнером, а не UI-тест.

На Mac: Product → Test (⌘U), либо выберите существующий симулятор через `xcrun simctl list devices available` и выполните:

```sh
xcodebuild -project BMSport.xcodeproj -scheme BMSport \
  -destination 'platform=iOS Simulator,id=YOUR_SIMULATOR_UDID' test
```

До рабочей эксплуатации на iPhone проверить: перезапуск с черновиком и завершённым отчётом; длинные русские/армянские тексты и конец последней страницы; PDF в Files/WhatsApp/Telegram/AirDrop; нехватку места и повторное сохранение; получение контейнера восстановления; клавиатуру, маленький экран и крупный системный шрифт. UI-тесты могут потребовать адаптации системных элементов Share Sheet под язык/версию iOS.

## Структура

`BMSport/` — приложение; `BMSportTests/` — unit; `BMSportUITests/` — UI; `AGENTS.md` — правила изменений. `scripts/Generate-Project.ps1` детерминированно пересоздаёт Xcode project из Swift-файлов (PowerShell, нужен только если меняется набор исходников). Версию persisted JSON меняйте с backward-compatible decoding и миграцией. Текущий внешний вид использует системные элементы; отдельная фирменная App Store иконка и публикация не входят в эту сборку.
